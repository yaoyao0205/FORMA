# 一万条规模压测（2026-11-09）

目标：验证「至少支持 10,000 个模型资产」这条硬指标，量出瓶颈到底在哪。

## 方法

为不污染真实库，给主进程加了 `FORMA_DATA_DIR` 钩子（设置后 `app.setPath('userData')` 指向隔离目录，和 `FORMA_SHOT` / `FORMA_SEED_DIR` 同类，生产环境不设就没有任何影响）。

压测数据：
- 1 万个真实 STL 文件（每个 284 字节、4 三角形、20×20×20 mm）放在 `/tmp/forma_stress`
- 1 万条 `models` 记录直接写进隔离库的 SQLite，路径全部指向上面这些真实文件，`imported_at` 递增，缩略图留空（走统一几何占位图）

这样能压到查询、分页、虚拟滚动、目录轮询；但不覆盖「一万张缩略图同时生成」这条路径（见限制）。

## 结果

| 指标 | 结果 |
| --- | --- |
| `COUNT(*)` | 0.26 ms |
| 首页 500 条查询 | 1.05 ms |
| 深翻页（offset 9500） | 2.19 ms |
| 文件名模糊搜索（命中约 1000 条） | 1.71 ms |
| 首屏滚动高度 | 36,153 px（500 条 / 125 行） |
| 全部加载后滚动高度 | 722,528 px（10,000 条 / 2,500 行） |
| 渲染进程 JS 堆 | 25 MB 稳定，滚动 100 次无增长 |
| 一万文件目录单轮 `readdir + stat` | 82 ms（监控每 8 秒一次，占空比约 1%） |

SQLite 完全不是瓶颈，瓶颈全在渲染层，所以虚拟化是必须的。实测滚动 120 次后仍稳定在 25 MB 堆占用、界面可正常渲染到底部最后一条（`model_09999.stl`）。

## 压测中抓到的真 bug（已修）

**滚到底只加载一页。** 首屏 500 条，滚到底触发一次 `onEndReached` → 加载到 1000 条 → 之后无论怎么滚都不再加载。

原因在 `VirtualGrid`：`endedRef` 只有「滚动位置离开底部区域」时才重置。程序化/连续滚到底时 `scrollTop` 始终贴着最大滚动高度，`!nearBottom` 分支永远不成立，于是「到底」触发位被一次性锁死。

修法：在 `useEffect` 里监听 `items.length` 变化并把 `endedRef` 置回 false —— 追加一页后自动解锁下一轮。

修复后实测：`sh` 从 36,153 → 361,278 → 722,528（10 页连续加载到全部一万条）。

**退出时的缩略图竞态。** 关窗后渲染进程还在收尾，`thumbnail:save` 打到已关闭的数据库，日志出现 `数据库尚未初始化`。修法：该 handler 捕获这条错误直接返回 `{ok:false}`（缩略图本来就会按内容哈希重建，不需要当成失败）。

## 已知限制

- 没有压「首次进入时 1 万张缩略图排队生成」：真实场景不会一次渲染一万张，缩略图队列按可视区 + 并发上限跑；这条路径需要用一批真实大模型单独验证。
- 一万文件目录扫描 82 ms 是冷缓存数据，文件系统热缓存会更快；HTDD/外接盘可能显著更慢。
- 深翻页用 `OFFSET` 仍是 O(n)，当前 2 ms 可以忽略；如果将来单库到十万级，再换 keyset 分页。
